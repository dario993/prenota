# Tariffe libere per opera – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sostituire i cinque tipi di biglietto fissi con un tariffario libero per opera (nome, prezzo, spunta «nascosta»), pacchetto escluso, convertendo i dati esistenti in locale e in produzione.

**Architecture:** due tabelle nuove (`tariffe` per opera, `prenotazioni_tariffe` con quantità e prezzo congelato); la prenotazione tiene solo pacchetto e anagrafica. La logica (calcoli, riepilogo, scelta delle tariffe nel modulo) resta pura in `src/lib/` e testata; API, Server Action e componenti la collegano. Una migrazione SQL idempotente, eseguita da `db-init` a ogni avvio, converte i database esistenti.

**Tech Stack:** Next.js 16 App Router, React 19, react-hook-form + zod 4, TanStack Query 5, Postgres con driver `postgres`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-24-tariffe-design.md`

## Global Constraints

- Importi in centesimi (`integer`); data/ora sempre `Europe/Rome`.
- Prezzi congelati: la prenotazione salva il prezzo di ogni tariffa al primo inserimento; cambiare il tariffario non tocca le prenotazioni salvate.
- Offline: si possono solo aggiungere prenotazioni, mai doppioni (id UUID + `on conflict do nothing`).
- Ogni route API e Server Action valida con zod e controlla sessione/ruolo (tariffario: solo admin).
- Nessuna nuova dipendenza.
- Interfaccia, testi, nomi di variabili e commit in italiano (`feat: …`, `fix: …`, `docs: …`).
- Ogni commit aggiorna la wiki interessata + `docs/wiki/15-registro-modifiche.md`; prima di ogni commit `npm test && npm run lint && npm run build`.
- Lavoro su branch `feat/tariffe` (da `main` a `67b3a62`), merge su `main` a fine piano.
- Il build è rotto dal Task 1 al Task 6 (i tipi cambiano sotto i componenti): per la regola «build verde prima di ogni commit», i Task 1–5 **non fanno commit**; il primo commit è alla fine del Task 6 e comprende Task 1–6 e la spec `docs/superpowers/specs/2026-10-24-tariffe-design.md`. Il Task 7 ha il suo commit.
- Esecuzione sull'homelab (deploy, trasferimento dati) solo con il via esplicito dell'utente al momento.

## Review Focus

1. Modifica di una prenotazione che usa una tariffa poi nascosta: la quantità resta visibile e salvata → test `tariffeDelModulo` (Task 1).
2. Due tariffe con lo stesso nome a parte maiuscole/spazi («Adulti» e « adulti ») → rifiutate → test `schemaOpera` (Task 2).
3. Payload con la stessa `tariffa_id` due volte o con quantità tutte a 0 e niente pacchetti → rifiutato → test `schemaPrenotazione` (Task 2); `tariffa_id` di un'altra opera → 400 «Tariffa non valida» (Task 4, verifica a mano).
4. Opera con tutte le tariffe nascoste e pacchetto nascosto → non si salva → test `schemaOpera` (Task 2).
5. Prenotazione in coda offline con una tariffa che non esiste più nel tariffario in cache → il riepilogo non si rompe (prezzo 0, nome «Tariffa eliminata») → test `righeConPrezzi`/`riepilogoEvento` (Task 1).
