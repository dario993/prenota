# Prenota Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web app Next.js mobile-first (ottimizzata anche desktop) per gestire locali, opere, eventi e prenotazioni teatrali con pacchetti ristorante, multi utente, con inserimento offline delle nuove prenotazioni.

**Architecture:** Un solo progetto Next.js 16 App Router. Postgres via driver `postgres` (SQL esplicito, nessun ORM). Logica pura in `src/lib/` testata con Vitest; scritture admin con Server Actions; letture client con TanStack Query da route `GET /api/*`; creazione prenotazioni con `POST /api/prenotazioni` idempotente così che le mutation in pausa possano riprendere offline.

**Tech Stack:** Next.js 16.2.10, React 19.2.3, Tailwind CSS v4, TanStack Query 5 (+ sync-storage persister), react-hook-form 7, zod 4, lucide-react, sonner, clsx, postgres 3, Vitest, TypeScript 5, ESLint 9.

**Spec:** `docs/superpowers/specs/2026-10-24-prenota-design.md` + wiki `docs/wiki/` (le pagine wiki sono il riferimento di dettaglio: 04 tariffe, 06 ristoranti, 08 database, 10 offline, 11 stile).

## Global Constraints

- Versioni esatte: `next@16.2.10`, `react@19.2.3`, `react-dom@19.2.3` (senza `^`). Altre: TanStack Query 5, react-hook-form 7, zod 4, TypeScript 5, ESLint 9 + eslint-config-next, Tailwind v4 + `@tailwindcss/postcss`.
- Nessuna dipendenza oltre a quelle elencate in Tech Stack (+ `@hookform/resolvers`, `@types/*`).
- Node locale è **20.20**: gli script in `scripts/` sono `.mjs` (niente TS eseguito da Node).
- Postgres locale già attivo (Homebrew `postgresql@17`), database `prenota`; `DATABASE_URL` in `.env.local`.
- Importi sempre in **centesimi** (`integer`); a video `formattaEuro` → `"49,00 €"`.
- Fuso orario **Europe/Rome** per input e visualizzazione di data/ora, indipendente dal fuso del server (il container Docker è in UTC).
- Testi UI, nomi di variabili/funzioni, commit in **italiano** (`feat: …`, `fix: …`, `docs: …`).
- Ogni task che cambia l'app aggiorna nello stesso commit la pagina wiki indicata, lo stato in testa ("da implementare" → "fatto") e una riga in `docs/wiki/15-registro-modifiche.md`.
- Server: ogni route API e Server Action valida l'input con zod e verifica sessione (e ruolo admin dove serve). Il client non è fidato.
- Ristoranti fissi `GIAMAICA | CASALE`, pasti `PRANZO | CENA`. Default pacchetto: teatro 2200, ristorante 2700.
- Capienza: avvisa, **non** blocca mai.
- Prima di ogni commit: `npm test && npm run lint && npm run build`.

## Review Focus

1. **Data/ora con server in UTC**: un evento inserito "2026-11-07T21:00" deve risultare 21:00 ovunque → conversione in SQL con `at time zone 'Europe/Rome'` e formattazione con `timeZone: "Europe/Rome"` (test in Task 2 e Task 7).
2. **Importi scritti con la virgola**: "22,50", "22.5", "22" → 2250/2250/2200; "abc", "-1" rifiutati (test Task 2).
3. **Modifica che porta i pacchetti a 0**: ristorante e pasto vanno azzerati, altrimenti il vincolo DB fallisce (test schema Task 3: lo schema li normalizza a `null`).
4. **Doppio tocco su Salva / doppio invio dopo il ritorno della rete**: una sola riga in DB (id UUID generato al montaggio del form, `on conflict do nothing`; verifica in Task 11 e 13).
5. **Email di login con maiuscole/spazi** e **utente disattivato con sessione aperta**: "  Mario@X.it " accede come `mario@x.it`; un utente disattivato perde subito l'accesso (verifica Task 5).
